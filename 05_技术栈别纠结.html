05｜技术栈别纠结：非程序员怎么做技术决策

《非程序员 AI 编程实战》系列第 5 篇 · 需求分析第 4-5 步：技术栈科普 + 技术决策

上一期我们用 MVP 思维，把一个模糊的想法收敛成了"先只做核心功能"的 60 分版本。

现在问题来了：这个 60 分版本，到底该用什么技术做出来？

  • 是用 Python？还是 JavaScript？还是听说过的 Java、PHP？
  • 什么是"前端""后端""数据库"？它们谁管什么？
  • 为什么有人一提技术栈就头大，而我作为非程序员，真的需要懂这些吗？

这一篇，我把软件开发技术栈讲深、讲透——但这篇的名字还叫"别纠结"：讲透的目的，恰恰是让你心里有底，不再当"选择困难患者"。看完，你只需要记住一句话结论。

结论先放这：以 web 应用开发为主，后端首选 Python（配 Flask 框架——最简单的 web 开发组合，进阶可选 FastAPI）；前端分三档：纯新手用 HTML，重点推荐 Vue.js，进阶用 React。国内工具 + 国内模型直接上手。

下面，我们从"盖房子用了什么材料"这种大白话，一路讲到具体该敲哪几个词。

一、技术栈是什么？用大白话讲

"技术栈"（Tech Stack）就是做这个软件用到的材料和工具，从上到下一整套组合。

  • 盖平房用砖和水泥；盖大楼用钢筋和混凝土——材料不同，但目的都是"住人"。
  • 做软件也一样：不同的语言、框架、数据库，组合成一套"栈"，但目的都是解决那个问题。

核心心法：技术栈是为需求服务的，不是反过来。 你的需求决定技术栈；而不是先学了一门技术，再去硬套需求。

顺带看清：技术栈是跟着时代走的（我们团队二十年）

光说"选什么"不够服人。把我（和团队）这二十多年的技术选型摊开，你就明白：技术栈是跟着时代走的，没有"永远最好"的语言，只有"当下最合适"的语言。

时代年份主语言数据库背景与选择逻辑
互联网时代2000 年前后PHPMySQL草根创业黄金期，LAMP（Linux+Apache+MySQL+PHP）套件一键建站，PHP 写网页简单直接，MySQL 是免费的关系型数据库。那个年代做网站，几乎就是 PHP + MySQL。
大数据时代2010 年前后JavaScript（Node.js 兴起）MongoDB数据量爆炸、结构多变，MongoDB 这类"文档型"数据库（存 JSON 似的自由格式）比死板的表更灵活；Node.js 让 JS 前后端通吃，团队用一套语言打通。
云原生 + AI 时代2015 年前后PythonPostgreSQL上云让运维变简单，AI 与数据科学崛起，Python 一统江湖；PostgreSQL 是开源关系型数据库里的"全能选手"，既能当传统表格库，又能存 JSON、做地理空间，配 Python 生态无缝。

每一次切换，都是因为业务形态变了（从建站，到大数据，再到智能）。今天你要做的恰恰是智能时代的产品——所以答案很清楚：Python 打头，PostgreSQL 兜底，前端 JS 收尾。 这也正是本系列从一开始就推"国内工具 + 国内模型"的底气：时代给了你 Python 这种低门槛利器，又有了 CodeBuddy、通义灵码这些国产工具，非程序员做产品，从来没这么顺过。

对新手，最舒服的做法是：先认全"软件有哪几种架构、一块应用由哪几部分组成、主流语言各自干嘛"，再照需求对号入座。下面三节，就是这份"认全清单"。

二、先分清架构：B/S 与 C/S（非程序员的必修课）

你做的作品跑在什么结构里，决定了用户怎么用它。最基础的分法是两种：

B/S 架构（Browser / Server，浏览器-服务器）

  • 意思：用户用浏览器打开一个网址就能用，不用安装任何东西。服务器在远端，处理所有逻辑。
  • 典型：网页、网页应用、以及微信小程序（小程序本质也是"在微信这个壳里跑的 B/S"）。
  • 为什么对非程序员最友好：不用安装、跨平台（电脑手机都能开）、好分发——发个链接就行。
  • 一句话记：B/S = 打开网址就用。

C/S 架构（Client / Server，客户端-服务器）

  • 意思：用户必须先安装一个客户端程序（Client）在设备上，客户端再连服务器。
  • 典型：电脑上装的微信、Photoshop（桌面软件），以及要从应用商店下载的手机 App。
  • 特点：能深度调用本机能力（摄像头、文件系统），但安装、更新、上架都麻烦。
  • 一句话记：C/S = 先装程序再用。

5 种产物形态，对号入座

产物形态架构用户怎么用
静态网页 / 网页应用B/S浏览器打开网址
微信小程序B/S（微信壳）微信里打开
手机 AppC/S应用商店下载安装
桌面程序 / 脚本C/S电脑上安装运行

本系列以 web 应用开发（B/S）为主——它门槛最低、最适合作品快速被看见。下面所有"讲深讲透"，都围绕 B/S 的 web 应用展开。

三、一个 web 应用的三块积木：前端、后端、数据库

别被词吓住。一个 web 应用，拆开就三块，用"开餐厅"一秒懂：

角色在软件里是什么餐厅比喻非程序员要懂到什么程度
前端 Frontend用户看到、点到的界面（按钮、输入框、页面）餐厅的菜单和点餐台知道"这是用户能看见的部分"即可
后端 Backend幕后干活的"大脑"：处理业务、算数据、调接口后厨厨师，按单做菜知道"逻辑和算账在服务器上跑"即可
数据库 Database存数据的地方，像公司的档案柜餐厅的仓库/账本知道"用户数据、内容都存在这"即可
  • 前端用的技术：主要是 HTML（结构）+ CSS（样式）+ JavaScript（交互）。你看到的每个网页，都是这三样。
  • 后端用的技术：一门服务端语言 + 框架（下文会讲 Python/Java/PHP/JS 怎么选）。
  • 数据库用的技术：关系型（如 MySQL、PostgreSQL，像 Excel 表格，行列整齐）或非关系型（如 MongoDB，像一堆自由格式的文档）。

关键区分：

  • 静态网页 = 只有前端（页面写死，不存数据）。
  • 网页应用 = 前端 + 后端 + 数据库（能登录、能存你的数据、能多人协作）。
  • 还记得第 4 篇说的"后端缺口"吗？很多人做第一个项目时，忘了网页应用还需要后端和数据库——这就是新手最常栽的坑。

四、web 技术栈全景：语言与框架怎么选

后端语言有好几种"门派"。给非程序员一张速查表，认个脸熟：

语言定位与特点非程序员友好度代表框架
PHP专为 web 而生，上手快，曾是小网站王者⭐⭐⭐Laravel、ThinkPHP
Java企业级"重型"语言，稳但繁琐，学习曲线陡⭐⭐Spring Boot
JavaScript / TypeScript前端的绝对主力；框架推荐 Vue.js（对初学者最友好）、React（生态最大）；Node.js 也能写后端⭐⭐⭐⭐（前端必学）Vue.js、React、Express
Python语法最接近自然语言，AI/数据时代首选，轻量框架出活快⭐⭐⭐⭐⭐Flask、FastAPI、Django

我们的推荐：分三档，按你"手生不手生"选

后端首选 Python + Flask——这也是最简单的 web 开发组合。 Flask 是 Python 生态里最轻的 web 框架，几行代码就能起一个网站：

from flask import Flask
app = Flask(__name__)

@app.route("/")
def hello():
    return "你好，这是我的第一个网站"

没有繁琐配置、不用懂一堆概念，非程序员从 0 到 1 最顺。Django 这类"全家桶"框架功能强但重，新手先用 Flask 就够。

首选语言：Python。 理由很硬：

  1. 非程序员能看懂——它的写法像英语句子，你甚至能半猜出代码在干嘛，方便验收 AI 写的成果。
  2. AI / 数据生态最强——当下所有 AI 库、数据分析、自动化脚本，Python 都是一等公民；你做的东西将来接 AI 最顺。
  3. Flask 轻量出活快——Flask 是个"微框架"，几行代码就能起一个网站，特别适合 MVP，不跟你讲一堆概念。
  4. 时代契合——进入云原生 + AI 时代，Python 是事实标准（团队一线经验印证，见本文开头）。

🥇 首推（最适合纯新手）：Python Flask（后端）+ HTML（前端）

很多新手一听到"前端"就想到要学框架。其实最简单的 web 开发，后端 Flask 直接返回 HTML 页面就行，前端根本不用框架。

  • HTML 是什么：它就是网页的"结构语言"——标题、段落、按钮、输入框，都是用 HTML 写出来的。你看到的每个网页底层都是 HTML。它不需要编译、不需要装环境，浏览器直接认。
  • 为什么适合新手：Flask 负责"收到请求 → 返回一段 HTML"；你让 AI 生成那段 HTML 即可。没有 JS 框架的概念负担，出错面最小，最不容易卡。
  • 适合场景：展示页、简单小工具、表单提交类轻应用——也就是第 4 篇说的 MVP 阶段。
  • 进阶时，再在 HTML 里加一点 JavaScript 做交互，也完全够用。

🥈 重点推荐（想要更完整的交互）：Python Flask（后端）+ Vue.js（前端）

当你的应用界面变复杂、交互变多（比如实时更新、多页面状态），纯 HTML 开始吃力，这时上 Vue.js：

  • Vue.js 是什么：一个 JavaScript 前端框架，对初学者最友好——中文文档好、上手直观，和 Flask 这种轻后端是天生一对。React 生态更大，但概念更绕，新手不必急着碰（进阶档会讲）。
  • 它解决什么：帮你把"前端页面"和"后端数据"干净地分开——Flask 专心提供数据接口（API），Vue 专心画界面、管交互。
  • 你不用先学 Vue 也能做——让 AI 用 Vue 写，你只管描述界面长什么样。

🥉 进阶推荐：Python FastAPI（后端）+ React（前端）

如果你将来要做纯数据接口（API）、或者追求更高性能与更规范的接口文档，可以认识一下 FastAPI——它和 Flask 一样是 Python 的轻量 web 框架，但更现代：

  • 特点：基于 Python 类型注解，自动生成交互式接口文档（Swagger），天生适合"前后端分离"——后端只吐 JSON 数据，前端框架来消费。
  • 前端搭档：React。React 是当前生态最大、组件最丰富的 JavaScript 前端框架，很多大厂产品（网站、后台系统、跨端 App）都在用它；配合 FastAPI 的"纯 API + 前端消费"架构，是业界常见的进阶组合。
  • React 比 Vue 难在哪：上手要理解组件、状态、数据流等概念，比 Vue 稍绕一些；但它功能更强、资料与组件库最多、市场招聘需求最大。等你做的东西要长期维护、或想积累一门可迁移的就业技能，再上 React 不迟。
  • FastAPI 和 Flask 怎么选：新手先用 Flask（概念最少、例子最多、AI 写得最稳）；等你熟悉了、且明确要做"后端只提供 API、前端用框架调用"的架构时，再切 FastAPI + React 不迟。
  • 一句话：Flask + HTML/Vue 是入门首选，FastAPI + React 是进阶组合。
💡 这三档怎么选？ 一句话：先拿"Flask + HTML"把 MVP 跑起来；界面复杂到 HTML 管不过来了，再让 AI 引入 Vue.js；要做长期项目、想积累就业技能了，再上 FastAPI + React。 别一上来就上框架，那是新手最容易掉的坑。
💡 一句话决策：后端 Python（Flask 起步，进阶可选 FastAPI）；前端按三档走——新手用 HTML，交互多了上 Vue.js，进阶选 React；数据库先用最简单的，够用就停。

让 AI 当技术顾问（把选型也甩给 AI）

你不用全懂上面这些，也能让 AI 帮你拍板。把这段直接发给你的国内 AI 工具：

"我要做一个【给小区业主用的报修网页应用】：业主提交报修，物业处理，进度可查。我是零基础非程序员。 请帮我：1）确认用 B/S 网页应用是否合适；2）给出最简单技术栈（建议 Python Flask 后端 + HTML/Vue.js 前端，是否要数据库先用假数据代替）；3）列我需要准备的账号和资料，按上手难度从易到难排。大白话讲，别堆术语。"

AI 会回你一份清晰方案，你拿着它进第 6 篇"环境搭建"直接开干。

六、避坑：技术选型最容易犯的 3 个错

坑 1：选择困难症（纠结综合征）——在"PHP 还是 Python""React 还是 Vue"上耗三天。记住：先跑起来比选完美重要一万倍。默认选 Python + 网页应用，错不了。

坑 2：盲目追新、追"听起来厉害"——非要用最新框架，结果自己看不懂、AI 也容易错。越简单、越主流越稳。 Flask 这种"老网红"恰恰最适合你。

坑 3：被术语吓住，以为"我不懂就做不了"——"前端/后端/API/部署"不用懂含义也能用 AI 做出来。你负责说"要什么"，AI 负责"怎么实现"。不懂术语是正常状态，不是障碍。

七、今天就能做的行动清单

  1. 拿出第 3、4 篇的问题与 MVP 定义（谁＋场景＋麻烦；核心功能清单）。
  2. 套第五节的决策对照表，先自己猜一个形态与技术栈。
  3. 把需求丢给 AI（第五节"让 AI 当技术顾问"提示词），让它确认/修正，要它"从易到难排准备清单"。
  4. 写死一句话："我这个做成【网页应用/小程序】，后端用 Python(Flask)（进阶可选 FastAPI）、前端按三档走：HTML（纯新手）/ Vue.js（交互多）/ React（进阶），数据库先用【假数据/PostgreSQL】，暂不上【复杂后端】。" 写下来，就锁住，不再纠结。
  5. 别急着学语言：下一期直接把环境跑起来——Python + CodeBuddy 怎么装、怎么跑，一步一步来。

形态和技术栈都定了，下一步就是把环境跑起来——第 6 篇《环境搭建不求人》见。
